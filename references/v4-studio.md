# VideoGuard 4.0 — Studio protocol

This version adds a local, advisory production layer; it never renders or submits generation. Keep one project JSON in a user-approved project directory (not the skill directory, not GitHub); do not store secrets, biometric templates or unnecessary private assets. In Claude.ai, keep a conversation ledger or export JSON when durable storage is unavailable. Never claim cross-session memory without a saved file.

## Senior workflow
1. **Creative contract:** goal, channel, audience, format, budget unit/cap, protected and editable elements, acceptance criteria. One high-impact question at a time. For narrative scenes use desire, obstacle, geometry, gaze and rhythm; for ads use communication intent rather than inventing a dramatic arc. Credit: Serge Shima / [Visual Skills](https://github.com/smixs/visual-skills), CC BY 4.0; these are independently written adaptations.
2. **Storyboard and identity:** establish a reusable reference sheet for each recurring person/product, with version, asset ID, approved visual attributes and allowed changes. Review identity sheet → scene still → video prompt. For strict logos/text/geometry consider deterministic compositing or constrained editing; no model can guarantee identity or geometry. Credit: [Square Zero Labs](https://github.com/Square-Zero-Labs/video-prompting-skill), character-sheet workflow.
3. **Prompt compilation:** Subject, Lighting, Camera, Technical (SLCT) is a useful checklist, not rigid syntax. Map only verified controls to exact provider model. Credit: [Creatify AI](https://github.com/Creatify-AI/ai-ad-prompt-guide), SLCT and quality-review inspiration.
4. **Three gates:** review brief, approve reference, review output. For each applicable criterion record evidence and PASS/FAIL/UNKNOWN; NA requires a reason. Never fake a PASS from mere prompt text or a single frame when temporal inspection is needed. Cost and capability evidence must be current. A changed reference, prompt, quote or dependency version needs fresh approval. Use a scoped attempt ID; stop when cap is reached or unknown. No paid action is authorized by the scripts.
5. **Failure repair:** use v3 debugger to find observed failed dependencies, retain unaffected accepted assets, and change one high-impact variable. Recheck the gates before another attempt. Log all charges, including rejected renders.
6. **Measure:** use paired baseline vs guarded tasks with fixed model/version, reference, settings and acceptance criteria. Randomize order where feasible, have a reviewer blind to prompt source, record all attempts and total actual costs. Report small samples as descriptive, not a savings guarantee.

## CLI contracts
From the skill directory: `python scripts/studio.py COMMAND input.json`. No external libraries. `storyboard` checks shot metadata and continuity, not pixels. `qa` requires reviewer evidence; it does not inspect the evidence automatically. `route` ranks options by supplied worst-case spend only; do not confuse this with best quality. `ledger` is an accounting/approval check, not a payment interceptor. No automatic persistence: save project JSON explicitly in Claude Code with consent, or copy/export manually.

- `storyboard`: project `{duration, identities, shots}`. Each identity `{id, version, reference_id, approved, locked:{attribute:value}}`; each shot `{id,duration,purpose,subject,action,camera,lighting,opening,ending,prompt,cast:{identity_id:{version,attributes}}}` plus optional `narrative:{desire,obstacle,geometry,gaze,rhythm}`, `continuous_from_previous`, and v3 handoff fields. Shot order defines the timeline. `cast` observations are supplied by the agent or human, not measured. Each recurring subject in a shot must be declared by the reviewer. Example `tests/studio-example.json`.
- `qa`: `{phase:"brief"|"reference"|"output",observations:{criterion:{status,evidence}}}`. Criteria listed in `scripts/studio.py` QA constant; missing evidence or required NA stays UNKNOWN. A FAIL blocks acceptance, not user access to a provisional prompt.
- `route`: `{unit,cap,options:[{id,unit,price,attempts,retries,capability_status,capability_source,quote_source}]}`. Supply actual current provider quote; separate USD, provider credits and planner tokens. Unknown quote or capability is excluded, not considered free. No cross-provider currency conversion. Include all extra costs in price or reserve separately.
- `ledger`: `{unit,cap,stages:[{id,inputs,version,status,depends_on,dependency_versions}],attempts:[{id,stage,unit,status,quote,quote_source,actual,accepted,approval}]}`. Status RESERVED/BILLED/RELEASED. One ID per attempt; replace RESERVED by BILLED after actual charge or RELEASED after verified no charge. Retried generations use a new ID. Every reservation needs explicit approval with `{confirmed:true,fingerprint:...}`. Compute fingerprint from `approval_payload(stage,entry)` (stage ID, inputs, dependency_versions, attempt ID, quote, quote_source, unit) using `fingerprint` command on that exact JSON. Inputs must include exact model, prompt, settings, and approved asset versions. Obtain approval **before** setting confirmed; SHA-256 is change detection, not authentication. A changed quote or prompt invalidates the approval. Unknown actual charge requires REVIEW; do not reserve more until resolved. Ledger cannot account for unlogged actions.
- `fingerprint`: any JSON object, canonical UTF-8 SHA-256; no secret material.
- `compare`: `{unit,pairs:[{id,settings_fingerprint,baseline:{unit,cost,attempts,accepted,first_attempt_accepted},guard:{...}}]}`. Fingerprint the common locked settings (not prompts). Use actual same-unit totals. Include failed attempts, record no-accept outcomes; if planner costs are in another unit report separately. Example `tests/trial-example.json` is synthetic, not measured results.
